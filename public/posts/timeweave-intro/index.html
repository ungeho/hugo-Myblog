予定の中身は見せずに空き時間だけ伝えるカレンダー「TimeWeave」

予定のタイトルやメモは見せず、「予定あり」と「空き時間」だけを共有リンクで伝えられるWebカレンダー「TimeWeave」。使い方と共有の仕組み、Claude CodeとChatGPTを使った開発の進め方を紹介します。

どんなアプリ？#

TimeWeave は、予定の内容は教えずに、時間の都合だけを相手に伝えられるWebカレンダーです。2026年10月25日に本番公開しました。

誰かと日程を合わせるとき、「その日は何があるの？」まで伝える必要はあまりありません。知りたいのは「この時間は埋まっているか」「この時間なら連絡がつくか」だけのことが多いです。かといって予定表のスクリーンショットを送ると、予定の名前まで見えてしまいます。

TimeWeave では、普段どおり自分のカレンダーに予定を入れておき、必要なときに共有リンクを作って渡します。リンクを開いた相手に見えるのは、「予定あり」と「空き時間」の時間帯だけです。

できること#

自分用のカレンダーとしては、ひと通りのことができます。

  • 月・週・日単位でのカレンダー表示
  • 時刻を指定した予定と、終日の予定の作成・編集・削除
  • 毎日・毎週・毎月の繰り返し予定（毎週は曜日を複数選べる）
  • 繰り返しのうち「この回だけ」の変更・削除
  • 予定ごとの「公開範囲」と「状態（Busy / Available）」の設定
  • 空き状況を読み取り専用で見せる共有リンクの作成・有効期限の設定・失効
  • スマートフォンでの表示
  • 日本語・英語の切り替え

ログインはGoogleアカウントで行います。ログインが必要なのは予定を管理する本人だけで、共有リンクを受け取った人はログインせずに見られます。

週表示では、時刻のある予定が曜日の列に並び、終日の予定は上の帯に出ます。斜線になっている「相談枠」は、空き時間として登録した予定です。

基本的な使い方#

予定を入れる#

カレンダーの空いているところを選ぶと、予定を追加するダイアログが開きます。

普通のカレンダーと違うのは、 「公開範囲」と「状態」 という2つの項目があることです。

項目 決めること
公開範囲 この予定の時間帯を共有リンクで伝えてよいか（非公開 / 予定ありのみ / 公開）
状態 その時間は予定が入っているのか（Busy）、連絡がつく時間なのか（Available）

名前が紛らわしいのですが、公開範囲を「公開」にしても、予定のタイトルが相手に見えるようになるわけではありません。どの設定でも、共有リンクの相手に渡るのは時間帯だけです。

逆に「非公開」も、時間帯まで必ず隠す設定ではありません。共有リンクを作るときに「非公開(private)の予定も busy として含める」がオンなら、非公開の予定も共有の対象になります。状態がBusyなら「予定あり」として、Availableなら、さらに空き時間の公開もオンにしたリンクで「空き時間」として相手に伝わります。このチェックがオフのリンクでは、非公開の予定はBusyでもAvailableでも共有の対象から外れます。

このチェックは 初期状態でオン なので、非公開の予定の時間帯を出したくない場合は、リンクを作る前にオフにしておく必要があります。

スマホで使う#

スマホでは、選んだ日の予定を並べる「一覧」と「月」の2つの表示になります。PCでできる操作はスマホでもできます。

予定を見せずに共有する#

共有リンクを作る#

カレンダー上部の「共有」から、共有リンクを作ります。

リンクごとに、次のことを決められます。

  • 非公開（private）にした予定も共有の対象に含めるか（初期状態はオン。後から変更はできない）
  • 空き時間（Available）として登録した時間を公開するか（非公開の空き時間は、上の設定もオンのときだけ）
  • 有効期限（空欄なら期限なし）

たとえば、仕事の相手には空き時間も含めたリンクを、別の相手には「予定あり」だけのリンクを、というように使い分けられます。ラベルは自分用のメモで、相手には表示されません。

共有をやめたくなったら、リンクを失効させればそのURLは使えなくなります。なお、URLはリンクを作った直後の一度しか表示されません。分からなくなったら、失効させて作り直す仕組みです。

相手に見える画面#

リンクを開いた相手には、読み取り専用の週表示が出ます。

塗りつぶしが「予定あり」、斜線が「空き時間」です。色だけでなく模様と文字でも区別しています。予定のタイトル・メモ・カテゴリ、予定の件数、共有した人のメールアドレスは表示されません。 予定が重なっていたり続けて入っていたりしても、ひとつの「予定あり」の帯にまとめて表示します。

「空いている時間」の扱いには気をつけている#

TimeWeaveでは、予定が入っていない時間を自動的に「空き時間」として出すことはしません。空き時間として相手に伝わるのは、自分で「Available」として登録した時間だけです。予定表の隙間が、本当に空いているとは限らないからです。

また、空き時間として登録した時間に「予定あり」が重なった場合は、予定ありを優先します。

「空いている」と誤って伝わるより、「予定がある」と伝わるほうが安全なので、こういう作りにしています。共有の対象になっている予定の中に、その期間を正確に計算できない繰り返し予定（現時点では毎月の繰り返しなど）が含まれる場合は、空き時間を出さずに「判定できませんでした」と表示します。

海外の人にリンクを送ったとき#

個人的に気に入っているのが、共有ページの言語と時刻の扱いです。

共有ページは、見ている人のブラウザの言語設定から日本語か英語を選んで表示します。時刻も、見ている人のブラウザのタイムゾーンに合わせて表示します。たとえば日本で作ったリンクを海外の友人が開いた場合、その人のブラウザの優先言語が英語なら英語の画面になり、時刻もその人のブラウザのタイムゾーンで表示されます。言語を決めるのは住んでいる場所ではなくブラウザの言語設定なので、海外にいても日本語を優先する設定なら日本語で表示されます。こちらの「14時」を相手の時刻に計算し直してもらう必要はありません。

ただ、何でも見る人に合わせているわけではありません。終日の予定がどの日にあたるかは、共有する側が設定したタイムゾーンで決めています。「10月13日は終日予定あり」というのは共有者のカレンダーの10月13日なので、見る人の側で日付の境界が動くと困るからです。そのため、時差が大きい相手の画面では、終日の予定が前日や翌日にまたがって見えることがあります。

言語は読む人のもの、終日の予定の日付は共有者のもの、と役割を分けています。

AIと共同開発してみて#

このアプリも、AIの補助を受けて開発しました。今回は Claude Code と ChatGPT を併用し、役割を次のように分けています。

担当 役割
自分 何を作るか・どういう仕様にするかの判断、最終的な決定、実機での確認、本番環境での操作の承認
Claude Code 実装、テスト、調査、不具合の修正、開発資料の作成
ChatGPT 設計や実装方針の検討、Claude Codeとは別の視点でのレビュー、リスクの洗い出し、Claude Codeへの指示の整理、検証結果の評価

流れとしては、ChatGPTと方針を相談して指示を整理し、Claude Codeが実装とテストを行い、その結果をChatGPTにも評価してもらい、最後に自分が判断する、という形が多かったです。

特に、AIが作ったものをそのまま公開しないことを意識しました。データベースの変更のように本番環境に影響する作業は、事前の確認手順と事後の検証をセットにして、一つずつ自分が承認してから実行しています。AIに任せて一気に進めるより時間はかかりましたが、そのぶん「何を確かめたか」が記録に残りました。

夏時間に悩まされた話#

開発で一番手こずったのが、タイムゾーンと夏時間（サマータイム）でした。日本には夏時間がないので普段は意識しませんが、海外の人と共有することを考えると避けられません。

夏時間がある地域では、年に2回、時計が1時間進んだり戻ったりします。そのため、

  • 時計が進む日には、存在しない時刻がある（例：ニューヨークの2026年3月8日 2:30）
  • 時計が戻る日には、2回ある時刻がある（例：ニューヨークの2026年11月1日 1:30）

という状況が起きます。

TimeWeaveでは、存在しない時刻を入れると「この時刻は存在しません」と表示して、保存できないようにしました。勝手に別の時刻へずらすと、利用者が気づかないうちに予定が変わってしまうからです。2回ある時刻のときは、「1回目」「2回目」をUTCとの時差つきで選んでもらいます。

さらに「毎週月曜9時」のような繰り返し予定では、どの国の9時なのかが決まらないと意味が定まりません。そこで、時刻のある繰り返し予定は作ったときのタイムゾーンを持たせ、夏時間をまたいでも同じ「現地の9時」になるようにしています。

使用した技術#

ここからは少しだけ技術的な話です。

技術 役割
React / TypeScript / Vite 画面と処理の実装
date-fns / date-fns-tz 日付・タイムゾーンの計算
Supabase Googleログイン、予定を保存するPostgreSQLデータベース
Vercel アプリの公開
Vitest ロジックの自動テスト

予定のデータはSupabaseのRow Level Security（RLS）で、本人以外からは読めないようにしています。共有ページは予定のデータを直接読みに行くのではなく、データベース側に用意した専用の関数を通して、空き状況の時間帯だけを受け取る作りです。共有リンクの文字列（トークン）もデータベースにはそのまま保存せず、ハッシュ化した値だけを保存しています。

テストは、日付計算などのロジックをVitestで確認しています。タイムゾーンを変えた複数の環境での実行、実際のブラウザ（Chromium）での操作確認、本番とは切り離したデータベースでの検証も行いました。公開後は、本番環境で主要な機能のスモークテストをしています。

もちろん、これで絶対に問題が起きないとは言えません。それでも、「表示しなくていい情報は最初から渡さない」ことを優先して作っています。

現状の制限と今後#

現時点でできないこと・気になっているところもあります。

  • 繰り返しは毎日・毎週・毎月のみで、「毎年」や「毎月第2月曜」のような指定はできない
  • 共有ページの計算では毎月の繰り返しをまだ正確に展開できないため、共有の対象になっている毎月の繰り返し予定がその期間にかかると、空き時間は「判定できませんでした」になる
  • 繰り返し予定の「この予定以降を変更」は未対応
  • 予定ごとにタイムゾーンを選ぶ機能はない（別の地域の時刻は、自分の端末の時刻に直して入力する）
  • ドラッグ＆ドロップでの予定の移動はまだできない

このあたりは、使いながら少しずつ改善していく予定です。

おわりに#

TimeWeave で作りたかったのは、「何をしているか」は言わずに、「いつなら大丈夫か」だけを伝えられるカレンダーです。

予定表を見せるのは少し抵抗があるけれど、日程調整のやり取りは減らしたい、という場面で使えると思います。アプリ内には使い方ガイドもあるので、気になった方は触ってみてください。
